---
title: Quickstart
description: Configure a host app, load runtime apps, and render a TailorKit screen.
---

This quickstart shows the host-side React flow: define a schema, create a
`tailor` instance, fetch runtime apps, and render the active screen.

## 1. Define A Schema

Your schema defines the components TailorKit apps can use and the screens the
host can expose.

```tsx
import { component, defineSchema, screen } from "tailorkit";
import { z } from "zod";

export const schema = defineSchema({
  components: {
    Button: component({
      fields: z.object({
        variant: z.enum(["primary", "secondary"]),
      }),
      callbacks: {
        onClick: {},
      },
      slots: ["default"],
    }),
  },
  screens: {
    "/home": screen({
      context: z.object({
        page: z.object({
          title: z.string(),
        }),
        user: z.object({
          id: z.string(),
          name: z.string().optional(),
        }),
      }),
    }),
  },
});
```

## 2. Create A Tailor Instance

Configure the React adapter with the runtime app registry URL and host component
renderers.

```tsx
import { createElement } from "react";
import type { ReactNode } from "react";
import { tailorKit } from "tailorkit/react";
import { schema } from "./schema";

export const tailor = tailorKit(schema, {
  baseUrl: "http://127.0.0.1:4175",
  components: {
    Button: ({ props, slots }) =>
      createElement(
        "button",
        {
          type: "button",
          onClick: () => {
            props.onClick();
          },
        },
        slots.default as ReactNode,
      ),
  },
});
```

`baseUrl` should point to a TailorKit runtime registry. In local development,
the experimental preview server exposes both `/apps` and built client assets.

## 3. Build Or Preview A TailorKit App

Run the TailorKit app preview server for the embedded app you want the host to
render.

```bash
tailorkit experimental-preview --cwd examples/apps/todo
```

The preview server serves:

- `GET /apps` for app registry metadata.
- `/client.js` for the built TailorKit app client.

## 4. Match A Host Screen

Use `ScreenMatch` where your host route knows which TailorKit screen is active.
The host supplies route params and typed context.

```tsx
<tailor.ScreenMatch pattern="/" screen="/home" context={context}>
  <HomePage />
</tailor.ScreenMatch>
```

## 5. Fetch And Render Apps

Use `tailor.useApps()` in your host route, then render each app with
`tailor.Screen`.

```tsx
function Home() {
  const { apps, error, status } = tailor.useApps();

  const context = {
    page: {
      title: "TailorKit client screen",
    },
    user: {
      id: "user_example",
      name: "Example user",
    },
  };

  return (
    <tailor.ScreenMatch pattern="/" screen="/home" context={context}>
      {status === "loading" && <p>Loading apps...</p>}
      {error !== null && <p>{error.message}</p>}
      {apps.map((app) => (
        <tailor.Screen key={app.id} app={app} />
      ))}
    </tailor.ScreenMatch>
  );
}
```

`tailor.Screen` renders the currently matched screen into each app. You can
render one app or many apps on the same host page.

## 6. Keep Routing In The Host

TailorKit does not match browser URLs. Your router should decide which component
is mounted, and that component should declare the TailorKit screen.

```tsx
<tailor.ScreenMatch
  pattern="/users/:userId"
  params={{ userId }}
  screen="/user"
  context={{ userId, user }}
>
  <UserPage />
</tailor.ScreenMatch>
```

Continue with [Screen Matching](/docs/screen-matching) for nested matches,
loading states, and direct app rendering.
