TailorKit apps run in a sandbox. That helps, but it does not make every value
safe automatically.

The production rule is simple: treat TailorKit apps as untrusted input. Your app
still owns validation, authorization, and trusted UI.

<Callout title="Your responsibility" type="warn">
  TailorKit limits what embedded apps can do directly. Your app still decides what data is accepted
  and which side effects are allowed. Read MDN's [XSS
  overview](https://developer.mozilla.org/en-US/docs/Web/Security/Attacks/XSS) for more background.
</Callout>

## Validate Fields

Keep schemas narrow. Prefer enums, bounded numbers, booleans, and structured
objects over broad strings.

<Callout title="Validate links">
  Do not render arbitrary strings as `href` or `src` values. Accept only safe protocols, usually
  `http:` and `https:`.
</Callout>

```ts title="./src/lib/tailor.ts" tab="Zod"
import { component } from "tailorkit";
import { z } from "zod";

const Link = component({
  fields: z.object({
    href: z.url(),
  }),
});
```

```ts title="./src/lib/tailor.ts" tab="ArkType"
import { type } from "arktype";
import { component } from "tailorkit";

const Link = component({
  fields: type({
    href: "string.url",
  }),
});
```

```ts title="./src/lib/tailor.ts" tab="Valibot"
import { component } from "tailorkit";
import * as v from "valibot";

const Link = component({
  fields: v.object({
    href: v.pipe(v.string(), v.url()),
  }),
});
```

## Keep Callbacks UI-Only

Callbacks are for UI events like `onClick`, `onOpenChange`, and
`onValueChange`. Do not use them to call APIs, mutate records, or start billing
or auth flows.

For trusted work, expose a host-owned [action](/docs/actions).

## Constrain Styling

Avoid arbitrary `style` objects, raw class names, and HTML. Prefer
[TailorKit primitives](/docs/layouts-and-styles) and theme tokens so apps can
feel native without controlling layout, positioning, or visual hierarchy.

<Callout title="Keep trusted UI recognizable">
  Destructive, billing, auth, invite, role, and permission controls should look and behave like
  host-owned UI. Do not let an embedded app visually replace those flows.
</Callout>

## Production Checklist

Before deploying:

- validate fields with narrow schemas.
- keep callbacks limited to UI events.
- avoid arbitrary styles, class names, and HTML.
