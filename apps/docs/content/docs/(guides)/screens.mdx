---
title: Scopes, screens, and viewports
description: Publish layered host context and render one app screen per viewport.
---

A **scope** describes the host situation, such as `/users/detail`. Its **context**
is the data the host supplies. A **viewport** is a place the host renders an app.
A **screen** is the app implementation selected for that viewport and scope.

TailorKit does not inspect the browser URL. Paths describe a hierarchy that the
host publishes explicitly.

## Define the host contract

```ts
export const tailorKit = createTailorKit({
  components: {},
  viewports: { navbar: {}, panel: {} },
  scopes: {
    "/": { context: z.object({ workspaceId: z.string() }) },
    "/users": { context: z.object({ canManageUsers: z.boolean() }) },
    "/users/detail": { context: z.object({ user: userSchema }) },
  },
});
```

Each scope declares only its own fields. Ancestor fields are composed into the
context received by app screens. A field must have one owning scope: duplicate
field names across ancestors are rejected by the type checker and runtime.

## Configure React once

```tsx
import { createTailorKitClient } from "tailorkit/react";
import type { tailorKit } from "./tailorkit";

export const client = createTailorKitClient<typeof tailorKit>({
  baseUrl: "https://example.com/api/tailorkit/",
});

declare module "tailorkit/react" {
  interface Register {
    client: typeof client;
  }
}
```

The registration types the standalone host hooks. Pass the stable client
configuration to `Root`; all rendering and hooks below it use React context.
Each root owns an independent registry, even when roots share a client.

```tsx
import { Root, AppView } from "tailorkit/react";

function Host({ app, children }) {
  return (
    <Root client={client}>
      <nav>
        <AppView app={app} viewport="navbar" />
      </nav>
      <main>{children}</main>
      <aside>
        <AppView app={app} viewport="panel" />
      </aside>
    </Root>
  );
}
```

Use `useApps()` below `Root` to load installed apps. The client configuration
no longer exposes bound React hooks or components.

## Publish each layer

Call `useScope` in the layout or page that owns the data:

```tsx
import { useScope } from "tailorkit/react";

function WorkspaceLayout({ workspaceId }) {
  useScope({ scope: "/", context: { workspaceId } });
  return <Outlet />;
}

function UsersLayout({ canManageUsers }) {
  useScope({ scope: "/users", context: { canManageUsers } });
  return <Outlet />;
}

function UserDetail({ user }) {
  useScope({ scope: "/users/detail", context: { user } });
  return <UserDetails user={user} />;
}
```

The deepest mounted scope is current. Only its ancestors contribute context.
Unmounting detail returns to the parent scope. Register one active route branch
per root; unrelated simultaneous branches are ambiguous.

Every declared ancestor must be mounted to render a descendant screen. A missing
ancestor produces the selected screen's error state rather than partial context.
Undeclared intermediate path segments do not require registrations.

## Implement screens per viewport

```tsx
const detail = createScreen("/users/detail", { component: UserTools });

function UserTools() {
  const { workspaceId, canManageUsers, user } = detail.useContext();
  return <UserActions user={user} canManageUsers={canManageUsers} />;
}

export default defineClient({
  viewports: {
    navbar: { screens: { "/": navigation } },
    panel: {
      screens: {
        "/users": generalUserTools,
        "/users/detail": detail,
      },
    },
  },
});
```

On `/users/detail`, the navbar renders `navigation` and the panel renders
`detail`. The panel does not also render `generalUserTools`. Parent contexts
compose; parent components do not.

Each viewport searches the active path, then its ancestors, ending at `/`.
Fallback never crosses viewport boundaries. An unsupported viewport or unmatched
scope renders nothing. Set a screen entry to `false` to explicitly stop fallback:

```tsx
panel: { screens: { "/": generalTools, "/users/detail": false } }
```

## Loading and errors

Keep the scope registered while its context is unresolved:

```tsx
useScope(
  query.isPending
    ? { scope: "/users/detail", status: "loading" }
    : query.isError
      ? { scope: "/users/detail", status: "error" }
      : { scope: "/users/detail", context: { user: query.data } },
);
```

Loading/error publications cannot contain context. Resolve the screen first,
then combine readiness for that screen and its ancestors. Errors take priority
over loading. Descendant loading does not block a parent screen in another
viewport. Loading never triggers fallback to a different implementation.

Apps can provide `loading` and `error` components to `createScreen`; omitted
handlers render nothing. `useContext()` is available only to the ready component.

Call the hook before early returns. When using Suspense or router loaders,
publish the loading/error scope from a boundary that actually mounts in that
state. A suspended component cannot publish a registration before it commits.
For Server Components, pass serializable data to a small Client Component that
calls `useScope`.

## Explicit mounts

A widget or dedicated page can choose its own scope independently of the current
route:

```tsx
<AppView app={app} viewport="panel" scope="/users/detail" context={{ user }} />
```

The override supplies that scope's own context; matching mounted ancestors still
supply inherited fields. It does not change other mounts or the current scope.
Explicit mounts use the same viewport-local ancestor fallback rules.

## Migrating

- Host `screens` becomes `scopes`; app `createScreen` retains its name.
- Declare host `viewports` and move app registrations into `viewports[name].screens`.
- Replace `tailor.Root` with `Root client={client}` and import `AppView`, `useApps`,
  and `useScope` directly from `tailorkit/react`.
- Replace `useCurrentScreen({ screen, ... })` with `useScope({ scope, ... })`.
- Publish only each scope's own context. Keep declared ancestor layouts mounted.
- Add a `viewport` to every `AppView` and regenerate app bindings.
