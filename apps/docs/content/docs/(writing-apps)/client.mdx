---
title: App client reference
description: Register TailorKit app screens and access typed screen context.
---

The app client is the runtime entry point for a TailorKit app. It maps screen
keys to Preact components and is loaded by the host's iframe-and-worker sandbox
runtime.

## `defineClient`

```ts
import { defineClient } from "@tailorkit/app";
import HomeScreen from "./screens/home";

const client = defineClient({
  screens: {
    "/home": HomeScreen,
  },
});

export default client;
```

Each key in `screens` must match a screen path from the generated TailorKit
types, start with `/`, and match the path used by its `createScreen` value.

## `createScreen`

Create a screen and read its typed context with `useContext()`:

```tsx
import { createScreen } from "@tailorkit/app";

const screen = createScreen("/home", {
  component: HomeScreen,
});

function HomeScreen() {
  const context = screen.useContext();

  return <h1>{context.page.title}</h1>;
}

export default screen;
```

The host publishes the current path and context. If the app does not implement
that exact path, TailorKit uses the closest parent path it does implement.

### Loading and error UI

Add these components only when the app needs custom UI for unresolved host
data:

```tsx
const screen = createScreen("/home", {
  component: HomeScreen,
  loading: LoadingScreen,
  error: ErrorScreen,
});
```

Both are optional. If omitted, the app renders nothing while the host publishes
that state.

| Member         | Description                                                                                           |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| `path`         | The screen path passed to `createScreen`.                                                             |
| `component`    | The Preact component rendered when the host context is ready.                                         |
| `useContext()` | Returns the generated context type for this path. It throws when called outside that screen's render. |

## Runtime behavior

When a host renders:

```tsx
<tailor.AppView app={app} />
```

TailorKit resolves the app's client URL, loads the client in the worker, and
renders the current screen into the app.

If the current screen is not implemented by the app client, the worker walks
back through its parent paths. For example, `/pages/detail` falls back to
`/pages` and then `/`. The nested context is safe for a parent screen because
the host schema requires nested contexts to include their parent context.
If the app implements none of those paths, TailorKit reports an error for that
app.

The exported client also includes `$meta` and `$runtime` properties used by the
TailorKit sandbox. Treat them as runtime details; app code should configure
screens through `defineClient` and `createScreen`.
