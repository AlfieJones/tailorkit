---
title: Writing apps
description: Build TailorKit runtime apps that target host views and components.
---

A TailorKit app is the embedded side of the integration. It is built separately
from the host app, served as a runtime client bundle, and rendered by the host
with `AppView`.

Apps use Preact and generated bindings, but they do not render directly into the
host DOM. They describe UI using the components the host exposes.

## Project shape

A generated app contains:

```txt
src/
  client.ts              # Registers the app's views
  views/default.tsx    # Implements one view
  tailorkit.gen.ts       # Generated host bindings; do not edit
tailorkit.config.ts      # Host URL, app ID, entry, and build options
package.json
```

## Register views

TailorKit apps export a client with views. Each view corresponds to a view
path from the host schema.

```ts
import { defineClient } from "@tailorkit/app";
import HomeView from "./views/home";

const client = defineClient({
  slots: {
    panel: { "/home": HomeView },
  },
});

export default client;
```

The host chooses which view is active. The app only implements the views it
supports.

Each value is created with `createView`; the registry key and view path must
match.

## Generate bindings

Run generation while the host's TailorKit handler is available:

```sh
pnpm generate
```

The generator reads the host schema configured in `tailorkit.config.ts` and
updates `src/tailorkit.gen.ts`. Regenerate after the host adds or changes a
view, component, action, callback, child content, or theme token.

Generated bindings expose host components and view props to the app.

```tsx
import { createView } from "@tailorkit/app";
import { Button } from "#tailorkit";

const view = createView("/home", {
  component: HomeView,
});

function HomeView() {
  const context = view.useContext();

  return (
    <Button onClick={() => {}} variant="default">
      Open {context.page.title}
    </Button>
  );
}

export default view;
```

`createView("/home")` is typed from the host schema, so `useContext()` returns
the composed context from the matching view and its mounted ancestors.

## Render host components

Components imported from `#tailorkit` render through the host's React adapter
component renderers.

The app renders `Button`; the host decides how that named component looks and
behaves. App code can pass only the fields, callbacks, and children declared in the
host contract.

## Call host actions

Generated actions are available from `#tailorkit` and always return promises.

```tsx
import { actions, Button } from "#tailorkit";

<Button onClick={() => void actions.echo("Hello from the app")}>Send</Button>;
```

Use actions for trusted server-side work. Use component callbacks for local UI
events. See [Actions](/docs/actions) for the security boundary.

## Build and preview

Run the TailorKit preview server while developing an app.

```bash
pnpm exec tailorkit experimental-preview
```

The preview server builds the app client and exposes an app registry:

```txt
GET /apps
GET /client.js
```

The host React client can point its `createTailorKitClient({ baseUrl })`
configuration at that preview server during local app development.

Build the production bundle without starting a server:

```sh
pnpm build
```

Deploy after authenticating the CLI with the host:

```sh
pnpm exec tailorkit login
pnpm deploy
```

## Keep apps focused

TailorKit apps should not own host routing or fetch host route data directly.
Use the context supplied by the current host view, then render UI using the
generated component bindings.

Apps should also avoid depending on generated-file implementation details.
Import its public components, actions, and types through `#tailorkit`, and let
`pnpm generate` replace the file when the host contract changes.
